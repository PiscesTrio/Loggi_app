> **A personal practice project, not production software.**
> Not hardened for deployment; do not point it at real data.

The Flutter client for a logistics management system: warehouses and stock, commodities,
delivery orders and their tracking, fleet and drivers, analytics and audit logs.

> Backend repository: https://github.com/PiscesTrio/Loggi_server

The models in `lib/app/data/api/` are **generated from the backend's OpenAPI document** — see
[Regenerating the API models](#regenerating-the-api-models). They are committed, so a clone
builds without running the generator.

## Tech stack

| | |
|---|---|
| **Flutter** | Dart 3 (`sdk: ^3.13.0`) |
| **State** | `flutter_riverpod` — `AsyncNotifier` / `AsyncValue` |
| **Routing** | `go_router` — `StatefulShellRoute` for the tabs, `redirect` for the auth gate |
| **HTTP** | `dio` + `dio_smart_retry`, behind a hand-written `ApiClient` |
| **Models** | generated by `openapi-generator` (`dart-dio`, `json_serializable`) |
| **Credentials** | `flutter_secure_storage` — Keystore / Keychain |
| **Maps** | `flutter_map` over GSI (国土地理院) tiles |
| **Charts** | `fl_chart` |
| **i18n** | `flutter gen-l10n` from `lib/l10n/*.arb` |

`get` and `get_storage` remain in `pubspec.yaml` for the one screen still on GetX (login) and
for reading the legacy token during migration. Everything else has moved.

## What it does

- **Sign in** with a password or an e-mailed code; the JWT is kept in the platform keystore
  and attached by an interceptor, so no screen handles it.
- **Master data** — commodities and warehouses, each with a table and an editor.
- **Stock** — what a warehouse holds, and recording goods in or out.
- **Deliveries** — the order list, filing a new one, and a tracking timeline on a map.
- **Fleet** — drivers and vehicles.
- **Analytics** — what moved in and out, by commodity.
- **Audit** — sign-in and operation logs.

## Getting started

### Prerequisites

- Flutter with Dart 3 (`flutter --version`)
- An Android/iOS device or emulator
- A running [Loggi Server](https://github.com/PiscesTrio/Loggi_server) — its README has a
  `docker compose up` path

### Configuration

The backend address is injected at build time. There is no address in the source and no
second copy to keep in sync: `lib/app/config/app_config.dart` is the only thing that reads
it.

| variable | default | meaning |
|---|---|---|
| `API_BASE_URL` | the Android emulator's host alias, port 8088 | API root. The built-in default only suits an emulator talking to a backend on the same machine; pass it explicitly for anything else. |
| `ENFORCE_HTTPS` | `false` | Refuses to start against a plaintext endpoint. Pass it for release builds. |
| `ENABLE_FLUTTER_DRIVER` | `false` | Opens the flutter_driver extension. While it is live the device swallows real keyboard input — that is the driver's `enterText` taking over, not a bug. |

### Run

```bash
flutter pub get

# Android emulator, backend on this machine.
# EMULATOR_HOST is the emulator's alias for the host — 10.0.2.x on the
# standard Android emulator, different on others.
flutter run --dart-define=API_BASE_URL=http://EMULATOR_HOST:8088/api

# Physical device over USB, backend on this machine
adb reverse tcp:8088 tcp:8088
# 127.0.0.1 literally: adb reverse forwards that port on the device itself.
flutter run --dart-define=API_BASE_URL=http://127.0.0.1:8088/api

# Physical device, backend on another host on the LAN — no tunnel needed
flutter run --dart-define=API_BASE_URL=http://LAN_HOST:8088/api

# Release
flutter build apk \
  --dart-define=API_BASE_URL=https://api.example.com/api \
  --dart-define=ENFORCE_HTTPS=true
```

The seeded demo account is `demo@loggi.example` / `demo1234`.

### Checks

```bash
flutter analyze     # must be clean; CI fails on warnings and infos too
flutter test
dart format --set-exit-if-changed .
```

## Project structure

```
lib/
├── main.dart                      # ProviderScope + secure-storage init
├── my_app.dart                    # MaterialApp.router: theme, locales, delegates
├── l10n/                          # app_zh.arb / app_en.arb + the context.l10n extension
├── features/                      # screens, by domain
│   ├── warehouse/                 # warehouse list, stock, the in/out dialog
│   ├── product/                   # commodity table and editor
│   ├── chart/                     # inbound / outbound analytics
│   ├── log/                       # one page, both logs
│   ├── settings/
│   ├── shell/                     # the tabbed shell and the page header
│   └── distribution/              # care tags (wire value vs label)
└── app/
    ├── config/app_config.dart     # the compile-time configuration, read once
    ├── auth/                      # the sign-in state the router redirects on
    ├── router/                    # go_router: shells, branches, the auth redirect
    ├── theme/                     # AppTheme, ColorPalette, StatusColors, ChartPalette
    ├── data/
    │   ├── api/                   # 36 generated models — do not edit by hand
    │   ├── network/               # ApiClient, ApiException, envelope + auth interceptors
    │   ├── repositories/          # one per domain; the only callers of ApiClient
    │   ├── auth/token_storage.dart
    │   └── map/                   # tile sources and their attribution
    └── modules/                   # what has not moved yet: login, and shared widgets
```

Two directories exist at once on purpose. `features/` is where a screen belongs;
`app/modules/` is what is left of the GetX layout, and it shrinks with each slice. The last
resident is `login`.

## How a screen is wired

```
screen (ConsumerWidget)
  └─ ref.watch(someProvider)          AsyncValue<T>: loading / data / error, all three handled
       └─ Notifier                    the actions the screen can take
            └─ Repository             the only thing that talks to ApiClient
                 └─ ApiClient         + interceptors: Bearer, envelope, retry
```

Nothing above the repository knows about HTTP, and nothing below it knows about widgets. The
`AsyncView` widget renders the three states so each screen does not invent its own — the
error state shows the server's own message, which survives the trip because the envelope
interceptor reads it from `msg` and the repository lets the exception through instead of
folding it into `null`.

## Regenerating the API models

`lib/app/data/api/` is generated and committed. Regenerate when the backend's contract
changes:

```bash
# 1. Fetch the document from a running backend
curl -s http://localhost:8088/v3/api-docs -o tool/openapi.json

# 2. Generate models only — the ApiClient and its interceptors are hand-written and stay
npx @openapitools/openapi-generator-cli generate \
  -i tool/openapi.json -g dart-dio -o build/openapi-gen \
  --global-property models \
  --additional-properties=serializationLibrary=json_serializable

# 3. Copy them in
cp build/openapi-gen/lib/src/model/*.dart lib/app/data/api/
dart run build_runner build --delete-conflicting-outputs
```

`lib/app/data/api/README.md` has the details. The directory is excluded from analysis in
`analysis_options.yaml`.
